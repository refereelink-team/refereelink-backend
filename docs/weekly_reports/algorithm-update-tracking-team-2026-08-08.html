从丢失到稳定

球员跟踪、逻辑实体重连与赛前监督分队的算法更新周报

本周结论：球员分队的主要风险来自检测短暂缺失和 Track ID 碎片化，而不是球队原型本身。当前方案保留 ByteTrack 作为底层跟踪器，增加显示级短时预测、逻辑球员实体层和语义标签继承；分队继续采用每场赛前人工 Track 标注、监督原型和 UNKNOWN 拒绝。

Algorithm Changes

01 / 球员跟踪

底层跟踪不变，恢复层前移

保留 YOLOv11 person + ByteTrack。6 帧短时预测只服务于画面连续性，不重新输入 tracker，不更新球队原型，也不参与越位、犯规等高风险判定。

02 / 逻辑实体

Track ID 之上再加一层身份

Track ID 短暂丢失后，通过位置、速度、球队语义、外观和唯一候选约束，把新 Track 重新绑定到旧的 entity_id。存在歧义时拒绝合并，避免两个相邻同队球员被强行粘连。

03 / 监督分队

赛前标定，比赛中冻结

操作员按 Track 标记主队、客队、守门员和裁判；系统提取高质量球衣 ROI，构建 HSV/Lab 与 MobileNetV3 外观原型。正式运行时原型冻结，证据不足输出 UNKNOWN。

Team Semantics

球队与角色分离

  • 球队：HOME、AWAY、NONE、UNKNOWN。
  • 角色：OUTFIELD、GOALKEEPER、REFEREE、UNKNOWN。
  • 守门员使用 HG / AG 语义，裁判不再显示 NONE REF，而是只显示 REF。
  • 未知目标不绘制最终视频标记，减少视觉噪声。
Final Video Rendering

输出层同步收敛

  • 球队使用稳定颜色：主队洋红、客队青蓝。
  • 普通球员显示 H10 / A39 等紧凑标签。
  • 脚底标记采用下半环，顶部开口，避免穿过腿部。
  • 标记只属于最终产出视频；检测、跟踪和分类数据结构不被改变。

Current Guardrails

明确不做的事

  • 不把预测框重新送回 ByteTrack。
  • 不使用预测框更新球队原型。
  • 不以球队颜色单独决定唯一球员身份。
  • 不在分队失败时静默切换 KMeans。
