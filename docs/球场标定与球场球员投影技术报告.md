# 球场标定、球场与球员投影技术报告

## 1. 背景与目标

本项目围绕足球视频分析，核心目标是在**单目转播视频**中完成三件事：

1. 从图像中稳定识别球场关键点（球场标定）；
2. 基于关键点估计图像到标准球场坐标系的单应矩阵（球场投影）；
3. 将球员（以及守门员、裁判、犯规位置）从图像坐标准确映射到俯视雷达图（球员投影）。

整套流程主要由 `PitchProjectionEngine`、检测模型、跟踪器与雷达绘制模块协同完成，并在实时模式下提供 `fresh/stale/unavailable` 三态可用性管理。

---

## 2. 系统总体架构

### 2.1 输入与模型

- **球场关键点检测模型**：`YOLO(PITCH_DETECTION_MODEL_PATH)`，逐帧输出 keypoints；
- **球员检测模型**：`YOLO(PLAYER_DETECTION_MODEL_PATH)`，输出人员检测框；
- **跟踪器**：`ByteTrack(minimum_consecutive_frames=3)`，为同一目标分配稳定 tracker id。

### 2.2 几何与渲染

- **几何核心**：`PitchProjectionEngine.update()`
  - 提取模型关键点；
  - 光流跟踪上一帧关键点；
  - 关键点融合与补点；
  - 鲁棒估计单应矩阵；
  - 输出投影结果与健康状态。
- **雷达渲染**：`render_radar()`
  - 以 `SoccerPitchConfiguration` 的世界坐标绘制标准球场；
  - 将球员底部锚点（`BOTTOM_CENTER`）透视变换到球场坐标；
  - 绘制各队球员与裁判点位；
  - 在可选场景下叠加犯规世界坐标点。

---

## 3. 球场标定技术细节

### 3.1 标准球场坐标定义

系统使用厘米级二维平面坐标：

- 长 `12000cm`、宽 `7000cm`；
- 内置 32 个结构化顶点（边线、禁区、球门区、中圈等）；
- 每个顶点绑定 `label` 与颜色，便于视频层和俯视图双向可视化。

这样做的意义是：检测模型输出的每个索引点，都可映射到一个固定世界点，形成可用于单应估计的对应对。

### 3.2 关键点观测提纯（Observation Filtering）

对于模型直接输出的关键点，系统做了多级筛选：

1. **置信度阈值**：`MIN_KEYPOINT_CONFIDENCE=0.35`；
2. **边缘剔除**：离图像边缘过近点剔除（`FRAME_EDGE_MARGIN_PX=8`）；
3. **亮线重标定**（关键优化）：
   - 在关键点邻域小窗口中寻找 V 通道最亮像素；
   - 要求亮度足够高（`MIN_LINE_BRIGHTNESS=130`）且饱和度不能过高（避免草地高饱和干扰）；
   - 将关键点微调到更贴近白线中心的位置。

该重标定策略可显著减少“点落在草地上”的误差，降低后续单应矩阵抖动。

### 3.3 光流延续（Temporal Continuity）

当模型在局部帧出现漏检时，系统基于上一帧观测通过 LK 光流补偿：

- 使用 `calcOpticalFlowPyrLK` 跟踪历史关键点；
- 通过运动幅度 z-score 过滤异常位移（`MAX_FLOW_OUTLIER_Z_SCORE=2.0`）；
- 通过色相差约束过滤跨区域漂移（`MAX_HUE_DELTA=25.0`）；
- 跟踪后的点再次执行亮线重标定。

这使得短时遮挡、快摇镜头下仍能维持关键点连续性。

### 3.4 几何补点（Synthetic Observation）

对于缺失关键点，系统按“世界坐标同 x/同 y 共线”原则拟合图像线：

1. 将现有观测点按世界 x（纵向组）与世界 y（横向组）分组；
2. 对每组使用 `cv2.fitLine` 拟合图像直线；
3. 求两组直线交点作为缺失点候选；
4. 仅保留落在扩展画面范围内的候选点（`SYNTHESIS_MARGIN_RATIO=0.2`）。

该机制可在点不足但结构线信息充分时，恢复更多可用于单应估计的约束。

## 4. 球场投影（单应矩阵）技术细节

### 4.1 求解策略

单应估计条件与流程：

- 至少 4 点（`MIN_KEYPOINTS_FOR_HOMOGRAPHY=4`）；
- 目标内点数至少 6（`MIN_INLIERS_FOR_HOMOGRAPHY=6`，若总点更少则降级到总点数）；
- 依次尝试 `RANSAC -> RHO -> LMEDS` 三种方法，提升不同噪声分布下的成功率。

### 4.2 质量门控

即使求得矩阵，也会进行二次验收：

1. 根据内点掩码统计内点数，不足则拒绝；
2. 计算反投影误差（world->image），平均误差需小于 `MAX_REPROJECTION_ERROR_PX=12`；
3. 仅保留内点对应观测用于可视化（减少错误点误导）。

### 4.3 稳态退化策略（Fresh / Stale / Unavailable）

- **fresh**：本帧新求得有效单应；
- **stale**：本帧求解失败，但允许复用上一帧有效单应；
  - 复用窗口由 `MAX_STALE_SECONDS=0.5` 换算成帧数控制；
- **unavailable**：连续失败超过窗口，彻底失效并清空历史。

该三态机制是实时系统稳定性的关键：短暂抖动不致“雷达闪断”，长期漂移又能及时止损。

## 5. 球员投影技术细节

### 5.1 锚点选择

球员、守门员、裁判统一使用检测框底部中心点（`BOTTOM_CENTER`）作为“脚下位置”近似，投影到球场坐标。

优点：

- 与地面接触点更接近；
- 对人体框高变化不敏感；
- 比中心点投影更符合战术位置语义。

### 5.2 投影与过滤

- 使用 `cv2.perspectiveTransform` 将图像锚点转换到世界坐标；
- 仅保留在 `[0, length] x [0, width]` 范围内的点，过滤场外误投影。

### 5.3 分类与可视化一致性

- 球员队伍 ID 来自在线 team classifier；
- 守门员队伍 ID 通过与两队质心距离最近原则推断；
- 颜色查找表 `color_lookup` 与投影后点位同步掩码过滤，确保“类别-位置”对齐不乱序。

### 5.4 犯规位置投影（扩展能力）

在有犯规模型时：

1. 从三帧缓冲生成运动区域 mask；
2. 计算 mask 质心（图像坐标）；
3. 用当前 homography 投影到世界坐标；
4. 落在球场范围内才显示为雷达橙色犯规点。

这说明投影引擎不仅服务球员点，也能承载事件空间定位。

---

## 6. 关键优化点总结

### 6.1 精度优化

- 亮线重标定（brightness+saturation 双阈值）；
- 多方法单应求解回退（RANSAC/RHO/LMEDS）；
- 反投影误差门控（12px）。

### 6.2 鲁棒性优化

- 光流跨帧补偿 + z-score 异常剔除；
- 色相差约束防止光流漂移；
- 几何补点增强约束；
- stale 复用机制平滑短时失效。

### 6.3 工程可观测性优化

- 返回 `homography_status`；
- 雷达上显示 `STALE HOMOGRAPHY / RADAR UNAVAILABLE`；
- 日志逐帧输出可用性变化和犯规定位信息。

---

## 7. 技术演进过程（从工程角度）

可归纳为四个阶段：

1. **基础可用阶段**：模型关键点 + 直接单应（能跑通）；
2. **质量收敛阶段**：加入关键点置信度/边缘过滤和重投影误差控制（稳定）；
3. **时序鲁棒阶段**：加入光流继承、色彩约束与 stale 复用（抗抖）；
4. **功能扩展阶段**：统一球员/守门员/裁判投影，并接入犯规位置世界坐标落点（可扩展）。

这个演进路径符合真实视频分析系统的规律：先打通链路，再控误差，再抗时序波动，最后承载更多上层业务语义。

---

## 8. 现有测试覆盖与结论

`tests/test_pitch_projection.py` 重点验证了三类关键行为：

1. 低置信度与边缘点会被正确过滤；
2. 离群点不会进入最终有效内点集合，且可得到 fresh homography；
3. 当前帧无点时可进入 stale 复用且不错误展示缺失点。

这三项测试覆盖了投影链路最关键的“输入清洗、鲁棒估计、失败退化”主路径。

---

## 9. 后续可继续优化方向

1. **自适应阈值**：按光照/转播风格动态调整亮度阈值与色相阈值；
2. **不确定性建模**：给每个投影点输出协方差或置信半径；
3. **相机运动先验**：融合全局相机运动估计，提高激烈镜头切换恢复速度；
4. **时序滤波**：在世界坐标侧做卡尔曼/EMA 平滑，进一步降低雷达抖动；
5. **多模态约束**：引入线段检测、分割球场线，和关键点共同优化单应。

---

## 10. 总结

当前实现已经形成一条完整、可运行、具备工程鲁棒性的“球场标定 -> 单应估计 -> 球员投影 -> 雷达表达”流水线。核心价值在于：

- 对噪声检测点具备较强纠偏能力；
- 在短时失败下保持输出连续；
- 能把空间信息稳定沉淀到统一球场坐标，支撑战术分析与事件定位。

在此基础上继续做阈值自适应和不确定性量化，可进一步提升跨场景泛化表现。
